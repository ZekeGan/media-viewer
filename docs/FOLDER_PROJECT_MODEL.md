# 資料夾與專案語意

本頁持有身分、值與跨專案語意；實體欄位／驗證以 [shared/model.ts](../shared/model.ts) 為準，位置見 [架構](ARCHITECTURE.md)，寫入安全見 [儲存規則](STORAGE_OPTIONS.md)。不要再維護一份平行 schema。

## 身分與值

- 每個受管資料夾有穩定 folderId；專案有 projectId 與獨立定義。同根／巢狀專案可重疊，路徑只供本機定位，不是可攜身分。
- 屬性值預設共用，專案私有覆寫須顯式建立；不因加入新專案自動複製成私有值。跨專案欄位不能只靠字串 key 相同推定身分。
- 欄位定義、型別、CELL 版面、資料值及來源資訊分離。目的專案決定顯示哪些欄位與版面，不覆寫搬入資料夾的原值。
- 缺值呈現空白或顯示預設；顯示預設不是已儲存值，也不自動成為搜尋值。型別不符保留原值並提示，不為了符合新版型別靜默轉換／刪除。
- 專案分類不改資料夾原屬性；只有可靠不符證據才提示，仍可檢視。導覽可進入的記錄／遊戲邊界規則另見 [工作區](WORKSPACE_REVISION.md)。

## 媒體分類轉換

舊 album／video／music／other 轉為 media 時，保留全部既有設定與身分，以可選 `Project.mediaSourceCategory` 保存原分類及內容模板選擇。模板不複製或覆寫，欄位值與資料夾記錄不遷移；同一保存流程依 revision 檢查、原子替換及備份，過期版本拒絕。介面提供預覽／取消及恢復原分類；恢復只更改分類，不覆蓋後續編輯。新建入口只列 media／manga／game，舊分類讀取及適用單檔預覽仍保留相容性。

## 移動、副本與復原

- 搬移保留可攜記錄與相對資產，由目的專案接續檢視。復原不依賴原設備的本機 DB／舊絕對路徑；POC 透過專案重新連結，無專案通用檢視留後續。
- 複製導致 folderId 衝突時先停止受影響寫入，要求明確處理，不能靜默合併或替原資料改身分。重疊專案與真正副本須區分。
- 共用／私有清理範圍分開；徹底清理後移入另一專案，依 C-66 視為新資料夾／新身分，不復活已清除的舊值。
- 已建立範圍、排除位置及遊戲邊界需隨可攜專案復原。不存在記錄不代表可以在導覽時自動建立。
