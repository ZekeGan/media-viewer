# 資料夾內容與專案檢視的關係

整理日期：2026-10-25。**跨專案讀取及「資料夾共用屬性預設、專案私有覆寫須顯式建立」已核定；實體 schema 尚未定。** 此頁優先於早期文件中「所有值預設以 project ID 隔離」的模型。

## 已確認的搬移情境

```text
專案 1：/1，分類＝相簿             專案 2：/2，分類＝漫畫
        └─ A（帶有自己的隱藏記錄）  →  /2/A
```

掃描 `/2` 時，專案 2 直接列出 A，套用專案 2 的 cell 版面。A 記錄內原有的內容仍可於詳情查看。專案 2 若配置 `MANGA_NAME` 而 A 只有 `GAME_NAME`，前者顯示空白或設定的視覺預設；不得默默把 `GAME_NAME` 改名、轉型或刪除。若能明確判定 A 的內容類型與專案分類不符，顯示提示圖示但不阻止檢視。`/2/A` 如又搬到遊戲專案，同理重新套用目的版面。專案分類是檢視設定，**不能因掃描而寫進 A 的記錄**。

## 資料責任與待設計格式

| 位置 | 建議保存 | 不應自動保存 |
| --- | --- | --- |
| A 的可攜記錄 | folder ID、有型別的自訂屬性、來源網站 ID／URL 與擷取值、資產相對引用、必要的 schema 版本。 | 「目前位於漫畫專案」這類由所在路徑推導的專案分類。 |
| 專案根設定 | project ID、根與深度、媒體分類、欄位／查詢別名映射、cell 版面、列數／分頁、保存搜尋。 | 把 A 的原值複製成專案專用的第二份真相。 |
| 本機 SQLite | 掃描後的目前路徑、搜尋／排序索引、縮圖及狀態快取。 | 跨設備唯一權威資料。 |

**已核定的識別原則**：資料夾屬性有穩定身分與明確型別；專案 cell 用屬性 ID 或明確映射取值，不以同名 key 猜測型別。`game.name`、`manga.name` 是可考慮的語意命名空間範例，使用者看到的 `GAME_NAME`、`MANGA_NAME` 可當別名；確切 ID 與命名方式尚待 schema 設計。若同一資料夾需要在兩個專案有不同自訂名稱，須**顯式建立專案私有覆寫**，共用值仍保持原樣。

**不符提示的規則**：專案分類本身不會寫入 A，不能只因資料夾進入不同根就斷定 A 類型錯誤。只有資料夾明確記錄的內容類型或可信來源可支持不符提示；資訊不足顯示「未判定」。內容類型若由使用者手動標記，也不得由專案分類自動填入。

**搜尋的規則**：查詢範圍是目前專案掃到的資料夾；無 key 搜尋 A 的所有可搜尋真實文字／標籤值，即使某欄不在專案 2 版面上。欄位提示區分「本專案版面欄位」與「資料夾實際有的其他欄位」。視覺預設文字不是 A 的資料，不能被搜尋命中。

**缺值與不相容**：目的版面缺值只呈現空白或設定的視覺預設，不寫回 A；型別不合顯示警示及原值入口，不強制轉型。專案私有覆寫的優先序與清理、舊 JSON 值的遷移，仍待具體 schema 與驗收範例。
