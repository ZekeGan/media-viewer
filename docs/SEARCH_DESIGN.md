# 搜尋規格與工程邊界

已選單一搜尋框＋欄位提示＋自由文字（方案 A）。本頁是語法及搜尋語意主文件；外框位置見 [工作區](WORKSPACE_REVISION.md)。程式入口：[query](../shared/query.ts)、[SearchIndex](../electron/search-index.ts)、[SearchDialog](../src/SearchDialog.tsx)。

## 範圍與身分

- SELECT 只在搜尋跳窗；有開專案預設當前，沒有則預設全部已連結專案。切範圍保留文字並重新查詢，不保留舊命中數。
- 搜尋真實保存的名稱／目前路徑／可搜尋屬性，不受目前版面是否有 CELL 限制；顯示預設不當真值。結果提供來源專案、路徑與命中資訊。
- 查詢別名不分大小寫、專案內唯一；底層值用穩定屬性 ID。跨專案同名 key 不推定同身分／型別；歧義提示選欄位，不猜測。
- 重疊專案保留來源關係與各自顯式私有覆寫，不能靜默合併。離線／未索引須說明結果不完整；重複 ID 衝突維持原問題處理。
- 選取結果與實際開啟分開；明確開啟才切來源專案並經 main 驗證定位，保留查詢。導覽不得為搜尋結果補建記錄。

## 搜尋介面

主要操作依序是關鍵字、範圍、結果及「開啟資料夾」。搜尋範圍顯示目前專案名稱；輸入可清除，更新期間停用舊結果。單擊選取、雙擊或 Enter 直接開啟；也可按明確開啟按鈕。結果列出名稱、來源專案、路徑及命中資訊，空結果提供縮短關鍵字／切換範圍提示。關鍵字旁加號建立常用條件，下方選單配對名稱／查詢並可逐列刪除；選取保留穩定欄位身分。搜尋範圍及關鍵字以 placeholder 與 aria 名稱表示；移除進階／索引展示，解析錯誤與不完整結果仍在主區明示。

## 搜尋對話框樣式

說明文字、取消／開啟資料夾按鈕所在區域的背景、邊框、間距及對齊須與對話框主題一致；窄視窗及長語系文字不得裁切或遮住操作。驗收三主題、條件選單／保存／刪除與鍵盤焦點，搜尋語意及開啟流程沿用上述規則。使用者圖 2 回報的 CSS 問題與完成狀態只在 [工作清單](WORK_ITEMS.md) 追蹤。

## 基本語法

| 輸入 | 語意 |
| --- | --- |
| 自由文字 | 無 key 的可搜尋值任意子字串 |
| `key:value` | 該專案別名／明確屬性的條件 |
| 空格 | AND |
| `name:chinese,pic` | 同 key 的兩個 AND 條件 |
| `"含 空格"` | 引號包住的文字 |
| `-key:value` | 排除緊接條件 |
| `A B ~ C` | 單層 OR：群組內 AND |
| `date:20251012`／`date:2025-10-12` | 同一天精確查詢 |

這是本產品自訂語法，不能宣稱與 E-Hentai 逐字相容。解析後顯示條件，未閉合引號／跳脫、缺 key／value、空 OR 群組要報錯。反斜線跳脫與特殊字元實際邊界以 parseQuery 及其測試為準；修改解析器時補針對性例子，避免另抄一份易漂移的語法實作。

## 索引與保存

Node SQLite 是可重建索引；目前以正規化值＋Unicode 三字元 grams 支援子字串，1／2 字查詢使用範圍掃描，並非早期研究的 FTS5 方案。資料改動成功後更新索引及畫面，分頁使用穩定順序。首次讀取／重建與已有索引的查詢分開量測，不能拿 SQL 耗時當 UI 反應時間。

每次同步按專案建立欄位查找表，仍比對每筆可搜尋輸入（來源專案、名稱、路徑、別名、型別與顯式私有覆寫後的實際值）；未變時略過文字正規化及索引寫入，不只依賴 revision 判斷。Library snapshot 的深複製隔離維持原契約。

常用搜尋保留名稱／原查詢字串並新增可選 queryAst（version 1），依穩定 attributeId 與型別保存語意。讀取舊字串不寫回；只有明確保存專案時才嘗試解析舊字串，歧義保留原文。欄位改名後仍查同一身分，顯示目前別名；欄位移除／型別變更明確報錯，不默默改查其他同名欄位。

## 欄位比較

明確數值／日期欄位的 value 可加 >、>=、<、<=、=，例如 score:>=4、date:<2025-01-01；負數、日期緊湊格式及排除／OR 沿用既有解析。純日期與日期時間分開，非法曆日／時間拒絕；未填不參與比較。一般冒號查詢仍是子字串，不改既有條件。是／否可用介面語言的「是／否」等用語或 true／false 搜尋。[查詢測試](../tests/decided-media.test.ts) 含改名、舊查詢保存、型別變更與數值／日期比較案例，執行範圍依驗證矩陣選擇。

穩定欄位身分與上述比較已有實作，不等同支援任意日期範圍簡寫或巢狀查詢。富文字、衍生公式及視覺條件建立器的延後方向見 [OPEN_DECISIONS](OPEN_DECISIONS.md)。

無 key 數字／日期的使用者格式及更複雜群組仍需細化，不能由已支援的欄位比較推定。舊方案比較、跨專案例子及效能研究見 [原稿](history/agent-docs-before-cleanup.md#search-design)，不是日常閱讀範圍。
