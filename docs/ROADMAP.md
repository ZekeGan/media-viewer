## 北極星與邊界

使用者選一個資料夾建立專案，依深度建立資料夾清單，用專案版面自訂每個資料夾的內容。同一資料夾可以出現在重疊專案中，資料不互相覆寫；連同圖片與版面複製到新設備後，不依賴本機資料庫也能復原。

使用者最新要求 POC 展示基本功能，MVP 逐步增加其他資料顯示與操作；**具體型別順序留待後續討論**。POC 最小演練已依 C-56 核定：指定資料夾、分析與顯示、簡化 cell 自訂、單筆文字值、每列／每頁設定、可攜保存、搬移重連、清理與即時更新。SQLite 是本機可重建索引的方向；視覺風格、雙向設備合併及閱讀／播放視窗不作此輪前置條件。

## 現在最需要解決的問題

1. **資料來源落差**：目前 `JsonStorage` 只寫 Electron `userData`，無法達成無本機資料庫復原。每資料夾可攜權威資料與 SQLite 索引分工已核定；先設計清理與重新連結，再處理 `S-01`。
2. **資料身分衝突**：目前 Column 以全域 key 儲存、Cell 以 key 對應；舊目標模型又預設所有值依專案隔離。最新決策是資料夾共用屬性為預設、專案私有覆寫顯式建立；穩定 ID 原則已核定，實體 schema 與舊值遷移待設計。
3. **掃描語意落差**：使用者已確認「顯示 1、2、3、4 層」與「只顯示第 4 層」，根為第 1 層；目前掃描內部從 0 起算，畫面沒有明確選擇兩種模式。仍需決定自動分析與隱藏記錄建立範圍，再處理 `V-01`。
4. **目前流程尚未閉環**：建立視圖的 IPC 不等待結果、畫面不刷新；編輯儲存與版面載入未接通。已核定保存後畫面立即更新，依新資料契約完成 `S-02`、`E-01`、`E-02`。
5. **技術與設計尚未落地**：現有畫面與功能按使用者估計不足 50%；Next.js renderer 遷移至 React + Vite 應獨立進行。UX/UI 先核定資訊架構，再定視覺風格；SQLite 先定權威資料與索引分工。
