# 畫面與功能地圖

整理日期：2026-10-25。以下描述目標產品，**不代表現有程式已實作**。標示「已確認」者來自使用者決策；「建議」是待審核的畫面安排或新增功能。UX/UI 視覺風格仍未定案。

## 目標畫面與主流程

下表列出目標功能，不表示每一列的全部細節都屬於 POC。POC 最小演練已依 C-56 核定，逐步驗收與每個畫面分別見 [POC 設計書](POC_DESIGN_PACKAGE.md)及[低保真線框](POC_WIREFRAMES.md)；後續資料型別與操作逐步加入 MVP。

| 畫面／區塊 | 要完成的事 | 狀態 |
| --- | --- | --- |
| 專案入口 | 選取根資料夾、媒體分類，建立與切換同根或巢狀的獨立專案；看到最近使用的專案。 | 分類只屬專案設定；入口版型為建議。 |
| 建立專案與掃描 | 設定顯示第 1 至 N 層或只顯示第 N 層，顯示掃描進度、錯誤與可取消操作。 | 深度模式、進度互動與每資料夾記錄已確認；實體格式待設計。 |
| 資料夾列表 | 套用目前專案 cell 模板；搜尋、排序、分頁，設定每列與每頁筆數；開啟資料夾。搬入別的媒體類型資料夾仍列出，可顯示不符提示。 | 預設依名稱／穩定 ID 排序，每列 2 筆、每頁 100 筆；POC 平面清單，其他兩種視圖在 MVP 逐步加入。 |
| 單筆資料編輯 | 側欄查看資料夾自身所有值、圖片及來源；可編輯自訂值。版面缺 key 留空或顯示視覺預設，原值仍於詳情可見。 | 側欄為已確認主入口；其他資料型別在 MVP 逐步增加，先後未定，見 [CELL 目錄](CELL_CATALOG.md)。 |
| 積木式版面編輯 | 左側選組件，中央格線拖放與調尺寸，右側改綁定欄位和樣式；用真實資料夾預覽，取消／復原／重做。 | 預設碰撞推開、無空間則拒絕已確認。 |
| 專案設定 | 修改深度、每列／每頁筆數、欄位定義、查詢別名及版面；顯示保存和索引狀態。 | 設定能力已確認；資訊安排為建議。 |
| 復原與問題處理 | 顯示唯讀、資料損壞、重複 ID、索引落後及跨設備復原狀態，提供明確重試或重建。 | 需求情境已確認；是否獨立畫面、細節待設計。 |
| 儲存資料清理 | 檢視單筆資料夾的可攜記錄並個別清除，或從一個入口清除所有已連結且可存取範圍內的程式資料。 | 清理能力與範圍原則已確認；部分失敗、目錄歸屬與恢復細節待 O-76、O-77。 |

首次建立專案即顯示可用的預設卡片，含真實資料夾名稱、目前路徑與「開啟資料夾」。圖片或自訂欄位無值時顯示編輯佔位，不產生假的使用者資料。跨專案搬移的完整例子見 [資料夾與專案模型](FOLDER_PROJECT_MODEL.md)；POC／MVP 候選組件見 [CELL 目錄](CELL_CATALOG.md)。

## 已確認要增加的功能，POC 後逐步加入 MVP

1. **批次編輯標籤與欄位**：多選後預覽影響筆數，處理部分失敗並保留可回復路徑；只編輯檢視器資料，不移動或刪除原始資料夾。
2. **保存常用搜尋**：保存查詢條件、名稱與排序；欄位改名時依 field ID 保持有效，型別改變時提示修正。

## 建議後續功能，尚未核定

1. **版面範本複製**：從既有專案複製版面與欄位定義到新專案，但產生新 project／field ID，不複製資料夾的值。
2. **索引與可攜資料健康狀態**：顯示上次掃描、待重建、唯讀與損壞筆數，讓復原流程可理解。
3. **進階查詢**：日期區間、數字比較、跨專案搜尋；在基本語法和 1,000 筆測量穩定後排期。
4. **外部中繼資料補充**：依遊戲、漫畫、影片、相簿、音樂分類擴充網站來源，先以來源連結／ID 提供候選，確認後存入個別資料夾。來源與階段待選；見 [外部資料設計](METADATA_ENRICHMENT.md)。

### 同一資料夾樹的顯示方式

| 模式 | 適用情況 | 取捨 |
| --- | --- | --- |
| 平面清單＋層級篩選 | 跨 1–5 層搜尋與批次操作；建議主視圖。 | 要顯示完整或相對路徑，否則同名資料夾難辨。 |
| 可展開樹／樹狀表格 | 同頁看祖先和子節點；適合探索層級。 | 深樹容易橫向擠壓，與分頁、搜尋命中展開的規則須另設。 |
| 麵包屑＋進入子層 | 每次專注一個父資料夾下的內容。 | 難以同時比較不同分支。 |
| 看板／分欄 | 按父資料夾、標籤或狀態分組。 | 不是嚴格樹；分組數多時不易掃視。 |
| 樹圖／蜂巢式總覽 | 看數量分布與相對規模。 | 不適合逐筆編輯、長名稱與精確搜尋，建議只作可切換的探索視圖。 |

**已確認三種視圖都要規畫**。POC 先完成平面清單與層級篩選；MVP 再做可展開樹與麵包屑，最後加入蜂巢／樹圖總覽。「只顯示第 N 層」仍依已核定的掃描規則。

媒體分類還會影響未來的瀏覽視窗：漫畫／相簿閱讀、影片與音樂播放等。使用者要求先擱置細部設計；目前只在資訊架構保留分類入口。

## POC 規模建議

以 1,000 筆資料夾作代表性測試資料量，另用 10,000 筆壓力測試；不要在資料模型設 1,000 筆硬上限。依 C-60 分別量測首次掃描／重建索引、基本搜尋、完整查詢、翻頁及單筆保存後的畫面更新。1,000 筆下暖機搜尋 200ms 內是**已核定的工程目標，尚未量測達標**；固定設備與查詢樣本待 O-78。
