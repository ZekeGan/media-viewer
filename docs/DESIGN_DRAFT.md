# 設計草案

**狀態：草案。** 本文件用於讓 agent 討論和實作可驗證的切片；檔名、JSON 結構、畫面風格及細部互動尚未定稿。已確認需求見 [PRODUCT.md](PRODUCT.md)。

**注意**：逐資料夾可攜記錄與共用值預設已確認；搬入另一專案應能讀取資料夾自身值，見 [資料夾與專案模型](FOLDER_PROJECT_MODEL.md)。實體格式仍須補上個別／一鍵清除、重新連結與離線範圍處理，見 [儲存與清理](STORAGE_OPTIONS.md)。

需要先核定的選項與順序見 [OPEN_DECISIONS.md](OPEN_DECISIONS.md)；後續階段見 [ROADMAP.md](ROADMAP.md)。

積木式 cell 編輯器的已核定互動與待決細節見 [EDITOR_DESIGN.md](EDITOR_DESIGN.md)。

`cell` 在產品描述中指一個可配置的顯示位置；它不必等於目前 `shared/main.ts` 的 `Cell` 資料型別。建議把資料夾的欄位值、renderer 設定與畫面排列分開，詳見 [TARGET_ARCHITECTURE.md](TARGET_ARCHITECTURE.md)。

## 概念模型

```text
資料夾 Folder（穩定身分、可攜記錄）
  └─ 共用有型別屬性（folderId / attributeId）與可選的專案私有覆寫
專案 Project（根資料夾、媒體分類、掃描模式、欄位映射、版面）
  └─ 掃描資料夾，renderer 依欄位映射顯示文字、圖片、標籤、動作等
```

方向：專案根目錄保存專案定義；每個資料夾保存其隱藏記錄，包含 folder ID、共用有型別屬性與必要時顯式建立的專案私有覆寫。圖片保存在可隨資料夾移動的位置，用相對引用連接。這是**概念圖而非正式 schema**；ID 格式、覆寫優先序及舊值遷移仍待設計。

例子：專案 A 可把別名 `tag` 映射到字串陣列屬性，專案 B 可把相同別名映射到不同的字串屬性；同名別名不代表同一屬性 ID 或型別。若兩個專案映射到相同的資料夾共用屬性，才讀到同一值；顯式私有覆寫另行標示。系統派生值（例如當前路徑）與使用者自訂值應有清楚區別，避免換設備後留下舊絕對路徑。

## 掃描與重疊專案

介面使用「顯示至第 N 層」及「只顯示第 N 層」。專案根資料夾標為第 1 層；實作內部可以從 0 計數，但對外語意要一致。專案 A 掃到巢狀專案 B 的根時，兩個專案可各用自己的版面讀取同一資料夾的共用值；專案私有覆寫須顯式建立，不以 B 的存在自動截斷 A 的清單。

需要測試的資料情境：搬移整棵樹、只搬移子資料夾、複製資料夾造成 ID 重複、資料夾記錄缺失或格式較舊、兩個設備分別修改後合併。衝突解決策略尚待決議。

## 畫面線框（資訊架構，非視覺稿）

```text
┌ 專案選擇 ─────────────── 新增專案 ─ 編輯顯示 ┐
│ 根資料夾 / 掃描模式與深度 / 結果數             │
├───────────────────────────────────────────────┤
│ 資料夾卡片或清單項目（每列筆數可設定，如 2）     │
│  圖片區  名稱 / 專案欄位 / 標籤 / 動作            │
│  [由專案 renderer 與版面決定實際內容]            │
│ 每頁筆數可設定（如 100）／切頁                   │
└───────────────────────────────────────────────┘

編輯模式 A（專案版面）：欄位定義 → renderer 與設定 → cell 排列 → 預覽 → 儲存。
編輯模式 B（單筆資料）：選一個資料夾 → 填寫自訂名稱、數字、標籤、圖片等值 → 儲存 → 返回清單。
```

風格、色彩、密度、側欄、拖放方式與響應式規則**未定案**。第一輪畫面實作應能驗證資訊與操作，不應把暫用樣式當作產品設計。

## 設計審核清單

- 可攜記錄是否足以在空白設備重建專案、欄位、版面、自訂值與圖片？
- 同一資料夾同時屬於兩個專案時，是否能獨立讀寫且不覆蓋？
- 掃描深度、包含根資料夾的規則是否有明確例子與測試？
- 寫入中斷、唯讀來源、版本升級與複製後 ID 衝突是否有可理解的結果？
- 使用者是否能看懂哪些內容會跟著資料夾移動，哪些只是本機快取？
