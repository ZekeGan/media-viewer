# 可攜儲存與清理安全

本頁持有資料安全及失敗語意，適用所有寫入／掃描／遷移／清理工作。身分與共用值語意見 [資料模型](FOLDER_PROJECT_MODEL.md)；位置與程式入口見 [架構](ARCHITECTURE.md)。原研究／舊方案見 [封存原文](history/agent-docs-before-cleanup.md#storage-options)。

## 權威與寫入

- 可攜 JSON 與受管資產是資料來源；SQLite／縮圖可重建，不能拿索引覆蓋原值。記錄有 schemaVersion、revision 與穩定 ID；實際契約查 shared/model.ts。
- 寫入採暫存、同步及原子替換，使用 revision／指紋偵測過期資料並保留可恢復備份。衝突不靜默覆蓋；單程式寫入序列不宣稱跨程序交易保證。
- 損壞原檔保留，復原不得用空預設蓋掉好資料；保留受損副本供診斷，未知檔案不當成垃圾刪除。格式升版／遷移先定義相容性、備份、失敗回復與驗收，再寫資料。
- 圖片 CELL 可用自身穩定位置 ID 綁定 FolderDetails.cellImages 中的 assetId，資產仍屬資料夾共用可攜資料；舊無位置 ID 的圖片 CELL 保留封面／首張相容回退。新的空白組件不自動借用首張圖片。新增綁定不自動初始化其他資料夾，失敗寫入須撤回新複製資產。
- 自訂圖片複製原檔到受管可攜資產，以相對參照保存；不覆寫原媒體，不依賴外部絕對路徑。縮圖是本機快取，原圖仍可回退。
- 掃描跳過 symlink／junction 及保留資料目錄；Windows 大小寫變體亦須排除。遊戲 ROOT 只可有自身記錄，內部不寫，明確層數設定也不能繞過邊界。

## 清理與範圍

- 先預覽可處理對象及影響，以 token／指紋重驗所有權及範圍，再執行；不為清理搬移或刪除原始資料夾／媒體。
- 個別私有覆寫、共用值與全部清理須清楚區分；只刪可證明屬於應用且在本次預覽內的資料。未知、其他專案／外來資料及備份不能順帶抹除。
- 「全部」只涵蓋已連結且可存取的資料，不能承諾離線／未連結／外部副本已清除。結果逐項列成功、跳過及失敗；中途失敗可重試／復原，不能只報整體成功。
- 清理後保留位置排除，所有涵蓋專案都要維持停止建檔，不能下一次掃描立即復活；只有確認該位置已不存在才解除，離線不可當消失。
- C-66：徹底清理後移入另一專案視為新資料夾；不靠舊本機索引找回原值。重連與副本處理仍須維持身分規則。
- 重新建立記錄不能只以 `.media-viewer` 是否存在判斷。主記錄缺失時，只有空目錄，或僅含內容／檔名身分均有效的已移除專案封存，才可建立新的 folderId；封存原樣保留且不自動復活舊專案。仍有備份時先要求明確復原；現用專案、資產、未知／損壞檔案或連結均阻止自動重建，不用新身分覆蓋遺失記錄的資料。重新連結沒有主記錄／備份的位置時提示重新新增，不藉此恢復已移除專案。

## 移除單一專案

此操作不等同清理全部資料夾。預覽只列該專案定義與存在私有覆寫的現用記錄；整批先重驗指紋，再以原子寫入移除對應 projectId 的私有值，保留共用值、其他專案值與復原備份。探測／保護邊界內的歷史子記錄保留並列略過；失敗逐項回報，不宣稱已清除離線、未列入或封存副本。

私有值寫入失敗時保留專案連結與設定，可重新預覽重試。成功後先持久化取消連結，再將該專案 .json／.bak 改名加上 .removed-<預覽 token> 封存；不是永久抹除。來源及目標都須在受管根內、目標不可已存在；封存不被一般連結自動載入。失敗保留檔案與錯誤，不順帶清理封存／未知資料。若要手動復原，先檢查未重用相同專案 ID，再從封存／folder.json.bak 比較恢復；沒有自動批次還原。

根目錄沒有共用欄位／圖片／內容設定、外來覆寫、其他連結的重疊專案或現用可攜專案，且 metadata 僅含已驗證根記錄與專案設定／封存時，移除預覽會額外列出根目錄清理與本機復原位置。執行時重新驗證整份檔案清單與指紋；先將完整根 metadata 複製至 userData/project-removals/<token>/，同步落盤並驗證雜湊、保存原位置清單，再逐項移除原位置的已驗證檔案（主記錄最後）、只刪空目錄。任何未驗證資料均使根記錄保留；子資料夾共用記錄不清理。備份／清理失敗逐項回報，晚期目錄失敗則從已驗證副本恢復缺失主記錄，不覆寫新檔。新專案不讀取本機復原區，根已清空時建立新的 folderId。復原區不自動清除，手動恢復前須按 manifest 確認根身分與現有資料，避免覆蓋後來建立的記錄。

## 必要驗證

只在自建／可丟棄資料樹驗證。依改動涵蓋成功、取消、過期 revision／衝突、缺檔／損壞／復原、部分失敗、重疊專案／副本、路徑逸出／junction、遊戲內不寫、未知檔保留；不相關情境不例行全部重跑。

使用者真實資料的批次寫入或遷移前必須有備份及失敗復原路徑。測試隔離與命令見 [驗證選擇](IMPLEMENTATION.md#驗證選擇)；省時間不得省去能發現資料遺失／誤刪的必要檢查。
