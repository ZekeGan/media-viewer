# POC 收尾與驗收紀錄

> 歷史設計／交付紀錄：保留原時點的範圍、提案與驗證，不例行追加，不作每輪前置檢查；當前入口見 [文件索引](../README.md)、[待查收](../WORK_ITEMS.md)。舊「待審／未實作」及完成測試數不代表現在狀態，亦不取代本輪驗證。


範圍：資料夾掃描 → 可攜資料 → 自訂 CELL → 單筆編輯 → 列表／搜尋 → 搬移重連 → 清理及復原。使用者已回覆上一輪手動操作「確認好了」，本輪補齊已列出的復原、草稿保護與效能觀察。

## 功能驗證對照

| 設計包 | 驗證與證據 |
| --- | --- |
| A-01 深度 | 資料測試驗證根為 1、1–N／只顯示 N、祖先記錄及排除自身目錄。 |
| A-02 基本呈現 | 使用者手動確認；Electron UI 驗證名稱、路徑與正式 preload／IPC 載入。開啟資料夾限定目前受管資料列。 |
| A-03／04 CELL | 使用者手動確認；UI 驗證拖入、縮放、復原／重做、保存即時更新；模板由可攜專案檔還原。 |
| A-05 單筆與圖片 | 資料測試驗證文字與圖片位元組可攜；UI 驗證保存即時更新、圖片經受控 media 協定實際解碼。缺值不建立假內容。 |
| A-06 排列分頁 | 使用者手動確認；UI 遍歷 1,005 筆共 11 頁，沒有重複或漏項。 |
| A-07 搜尋 | 以目前專案名稱／路徑任意子字串搜尋；排序結果重用。UI 量測含自動化往返與兩次畫面更新。 |
| A-08／09 搬移重連 | 資料測試以另一專案／空白 userData 讀回原值、模板及圖片；目的 CELL 依 attributeId 綁定。 |
| A-10 失敗與復原 | Windows 真實拒寫 ACL、損壞 JSON、重複 ID、磁碟滿模擬、暫存中斷、版本衝突；根／專案可由 UI 明確復原，損壞原檔與有效備份保留。 |
| A-11／12 清理與 O80 | 清理前後內容變更則拒絕；未知檔／原始媒體保留；重疊專案相對排除可攜；搬入新位置分配新 ID。 |
| A-13 重疊專案 | 同根多專案有各自模板，共用記錄不被掃描覆寫；重複身分另有確認流程。 |
| A-14 新增發現 | 手動／重新聚焦掃描，停止記錄保留；取消後再次掃描補齊，已完成記錄 ID 不變。 |

草稿保護另外涵蓋：單筆文字、CELL 模板、專案設定與新增專案；關閉／重新載入可選返回編輯。掃描或寫入尚在執行時，先完成／取消操作才能關閉。測試只使用 `.test-output/`，未掃描使用者媒體。

## 效能取捨

- 已移除逐筆啟動 `attrib.exe` 的成本，改為一次 PowerShell 程序，以 stdin 傳入已驗證的目錄；不組合使用者路徑為腳本或萬用字元。
- 掃描最多同時處理 8 個獨立資料夾。取消時完成進行中的寫入；批次隱藏失敗會回報並在下次掃描重試。清理後重新啟用會重新設隱藏。
- 搜尋重用已排序資料，並共用一個排序比較器；沒有增加 SQLite 或新套件。
- 首次寫入仍保留磁碟同步、版本檢查與備份。剖析顯示磁碟同步是剩餘主要成本；首次建檔仍需等待，不能宣稱已大幅提速。實測數字列於 IMPLEMENTATION.md。

## POC 結案界線

此輪驗證可支持核心概念與下一階段風格選擇。正式發布前仍需驗證真實斷電／儲存裝置故障、長時間使用、不同 Windows 設備及安裝包；本輪的磁碟滿驗證為故障注入，不是真正填滿硬碟。

SQLite 索引、完整 key/value 搜尋、其他 CELL 型別、圖片 CELL、私有覆寫建立 UI、批次標籤、常用搜尋及媒體閱讀／播放留在 MVP 規畫。首次建檔效能仍是後續改善項目，不以刪除持久性保障換速度。

視覺風格待使用者從 [三種方向](../DESIGN_STYLE_OPTIONS.md) 選擇；設計稿中的封面與標籤為未來呈現示意，不代表新增 POC 承諾。
