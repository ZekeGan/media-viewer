# 已核定的方向

整理日期：2026-10-25。依使用者在對話中的明確選擇記錄。這裡核定的是**產品與架構原則**；實際檔名、schema、函式庫及部分操作細節仍由 [OPEN_DECISIONS.md](OPEN_DECISIONS.md) 追蹤。現有原型可大幅改寫，以完成目標功能為準。

**O-47 已釐清**：使用者需要單個子資料夾搬移後仍能讀回自身資料，因此保留每資料夾可攜記錄。先前清理成本疑慮改由程式內個別清除與一鍵清除全部受管資料處理。實體格式、清除範圍、移出專案根後的重新連結及單獨資料夾是否能還原完整專案版面仍待設計；不能把「有隱藏檔」誤解成「已具備可靠清理」。

**值的歸屬已改定**：C-02 及舊架構文件曾將自訂值預設放在 `projectId + folderId + fieldId` 命名空間。最新決策採資料夾共用的有型別屬性為預設；專案只配置欄位映射與版面，真正需要不同值時才顯式建立專案私有覆寫。舊示意圖不可沿用，細節見 [資料夾與專案模型](FOLDER_PROJECT_MODEL.md)。

## 即時更新的最低驗收

程式內新增專案、修改某資料夾欄位值、調整專案版面或列表設定並成功保存後，當前畫面及相關清單立即更新；失敗時顯示錯誤，不把未保存值當成已完成。重新啟動仍一致是額外的持久性驗收，不能代替即時更新。外部程式直接修改資料夾記錄時，在視窗重新聚焦或手動重新掃描時同步。

## 隱藏記錄的可見性目標

使用者希望一般操作時感覺不到資料夾內的記錄。產品 UI 永遠不把自身記錄列成一般資料；Windows 版應使用隱藏屬性，並排除自己的記錄目錄於掃描與搜尋。這能降低日常可見度，**不能保證在啟用「顯示隱藏檔」的檔案總管或其他檔案工具中完全不可見**。可攜性要求也不適合把資料只放入 Windows 專屬儲存機制。確切檔名與 Windows 屬性方案仍需技術設計。
