## 現行閱讀器與資訊配置（2026-10-27 使用者更新）

漫畫屬性及資訊 CELL 保持獨立，僅共用 [統一媒體工作區](WORKSPACE_REVISION.md#統一媒體工作區) 的大視窗外框與同資料夾圖片佇列。大視窗預設覆蓋應用程式，下面的系統全螢幕是明確啟用的沉浸操作，不能在開啟檢視器時自動觸發；一般圖片需明確選擇漫畫閱讀模式，不自動改寫分類。

- 大量圖片沿用 [相簿效能基線](ALBUM_VIEWER_DESIGN.md#檔案與效能基線)：內容分批、可見範圍虛擬化、固定縮圖網格及非同步縮圖快取；保留 200 張分組與原始閱讀順序。
- 漫畫內容標頭的「編輯漫畫展示」開啟本專案漫畫資訊 CELL 模板；保存到 contentCells.manga，CARD 方案與 cells 保持獨立。TOP 遵循 [右側內容](WORKSPACE_REVISION.md#右側內容與覆蓋層) 的條件式顯示，只回捲目前內容區。
- 閱讀器上方分成頁碼導覽、單／雙頁與閱讀設定、縮放與沉浸閱讀；退出 ICON 在右上，圖片資訊在底部。首張獨立與 RTL 在工具列的閱讀設定中。
- 漫畫移除寬度／高度適應按鈕及 W／H 快捷鍵。圖片預設等比貼齊上方工具列與下方資訊列之間的實際可視高度，移除固定上下留白；縮放以貼合可視高度為 100% 起點／縮小下限，可繼續放大至 1000% 看細節（可調上限），不限制為原圖像素或可視區最大高度。放大後可拖曳平移，過寬頁面／雙頁可橫向拖曳，RTL 從右側開始。保留滾輪縮放與重設。相簿原有適應功能不受影響。

2026-10-28 使用者已確認：不希望額外縮小造成留白，預設與縮小下限皆維持上述貼合可視高度的 100%；不採先前推薦的 50% 下限。此項沿用現行程式，保留放大、平移與一鍵重設。
- 「沉浸閱讀」（F11，保留 T）進入作業系統全螢幕，即使應用原本為一般視窗也適用，並隱藏上方工具列、底部資訊與右上退出；再按 F11／T 或 ESC 退出沉浸後保留閱讀器，恢復原視窗狀態。滑鼠移到頂緣不叫出介面，以 F11／T 或 ESC 恢復。關閉閱讀器會釋放本閱讀器取得的全螢幕；閱讀設定／頁碼選單先關最上層。
- 頁碼、縮放按鈕與方向箭頭採 [共用閱讀器操作](UI_RULES.md#共用閱讀器操作)。鍵盤翻頁後閱讀區不顯示預設白色焦點框，工具按鈕保留鍵盤焦點提示。雙頁整組解碼後才原子換頁，等待保留舊頁；預載相鄰組、限制快取，快速操作只提交最後要求。圖庫背景 GIF 暫停。
- 閱讀設定清楚顯示目前「由右至左／由左至右」，可切換；沒有已存方向偏好時預設由右至左，既有明確偏好保留。
- 單頁與雙頁皆以整個閱讀區為基準只有一組左右點擊熱區；右至左時左側下一頁、右側上一頁，左至右時反向。雙頁不在每張圖片各建立一組熱區，避免出現重複翻頁區或一次點擊翻兩次；拖曳平移／縮放操作不得誤觸翻頁。

## 漫畫檔案模式入口

漫畫專案不顯示中央「檔案」檢視入口，中央保留資料夾導覽、右側維持漫畫內容；舊偏好若留在檔案模式則回退資料夾模式，保留來源資料與閱讀能力。

一般媒體專案在大視窗切換到漫畫閱讀模式，仍保留底層媒體檔案瀏覽；不停用共用檔案列舉、刪除來源資料或改寫專案屬性。早期漫畫／相簿共用檔案總覽表示底層能力共用，不代表漫畫必須保留獨立的中央檔案入口。

## 2. 已確認的閱讀視窗（本輪圖 2）

- 視窗採程式內全畫面覆蓋層，退出鍵為 ESC（C-85），不以此承諾獨立原生視窗。
- 點哪張圖，就從該圖開始，而非固定回到第一張。
- 工具列位於上方，從左到右依序為：頁碼導覽、單／雙頁、閱讀設定、縮放與沉浸閱讀；寬／高適應已移除。每項都需要快捷鍵。
- 雙頁時頁碼選項顯示區間，例如 `1–2`、`20–21`；這些是格式例子，不表示已決定封面及奇偶頁配對規則。

## 3. 已核定快捷鍵與工具行為建議

鍵位依 C-76 已核定；目前採單頁起始、手動方向／首張獨立、Tooltip 與 F11／T 沉浸閱讀；寬／高適應的手動切換已移除。其餘數值及復原時機仍屬可調基線。

| 功能 | 已核定鍵位 | 建議行為 |
| --- | --- | --- |
| 上一頁 | RTL：→；LTR：← | 單頁前一張；雙頁前一組。第一組停用，不循環；提示及按鈕動作跟隨方向。 |
| 下一頁 | RTL：←；LTR：→ | 單頁後一張；雙頁後一組。最後一組停用，不循環；提示及按鈕動作跟隨方向。 |
| 單／雙頁 | D | 手動切換，預設單頁；切換時保留目前圖片的定位。雙頁規則見下節。 |
| 頁碼選擇 | G | 聚焦可搜尋的頁碼選擇器，單頁顯示頁碼，雙頁顯示區間，Enter 跳轉。大量選項避免全部同時渲染。 |
| 沉浸閱讀 | F11／T | 進入／退出系統全螢幕；隱藏全部介面，移到頂緣維持隱藏。 |
| 返回／退出 | ESC | 先關選單，再退出沉浸，最後關閱讀器；每次只處理一層。 |

漫畫高度依實際閱讀區計算，工具列換行、視窗大小及全螢幕改變時更新；不以捲軸出現與否反覆修正尺寸。圖片比例不同時，不把雙頁各自硬拉成相同寬高。切換圖片建議回到新頁頂端，調整視窗則重算縮放但不更換頁碼。

工具按鍵以 Hover／鍵盤聚焦的 Tooltip 顯示快捷提示（C-76、C-85），例如「沉浸閱讀　F11／T」；按鈕標示目前模式。輸入欄位、頁碼搜尋或選單操作中不攔截打字及游標鍵。

## 4. 已採單／雙頁方向與配對基線（C-85）

- **首版先手動切換、預設單頁**，降低視窗變寬就意外換頁或改配對的情況。
- 提供由左至右／由右至左設定，無已存偏好時預設由右至左；顯示語意及點擊熱區依上述規則。
- C-85 採首張獨立的手動開關，不再自動推定首圖是封面；未來其他特殊配對需求另行提出，不由分類猜測。
- 建議將選項改名為「首張獨立顯示」，預設關閉，只在雙頁模式生效。開啟時為 `1`、`2–3`、`4–5`；關閉時為 `1–2`、`3–4`、`5–6`，不自動推定第一張是封面。
- 放在單／雙頁按鈕的閱讀選項 Popup，讓使用者看到配對結果，與 Tooltip 分開；C-85 已採每筆閱讀偏好獨立保存，具體可攜 schema 待設計，不變更分類或原圖。
- 頁碼區間依檔案順序表示；方向改變圖片左右擺放與各方向翻頁意義，不改原始頁序或配對。
- 尾端剩一張時單獨置中；不把它放大填滿兩頁，不把封面或缺頁誤當成空白圖片。
- 一個圖片檔本身已是跨頁時，可手動回單頁；自動辨識寬圖及自動配對先保留後續，不列首版必做。

## 5. GIF：已確認原則與效能細則

大量動圖會持續涉及圖片解碼與繪製。圖片尺寸、幀數、播放數量及設備都會影響成本，不能只按檔案數承諾順暢；以下是工程判斷，目前未執行本專案 GIF 效能測試。

| 選項 | 體驗與取捨 |
| --- | --- |
| **可見範圍播放，視窗外停止（已選）** | 可見範圍內的 GIF 播放，離開後停止。使用者未採用固定播放數上限；先前的 4 張只是原型建議，不得直接套成產品限制。 |
| 靜態縮圖，Hover／點按才播放（未選） | 保留作省資源模式候選，不替代目前已選的可見範圍播放行為。 |

已確認原則與建議實作細則：

1. 可見區播放、離開停止已確認。技術上建議替換靜態預覽／卸載動畫來源並保留占位；附近可預載縮圖，但不可因此在可見範圍外播放。圖片很多時再配合可視範圍渲染，不限制可瀏覽的總數。
2. 不能把「lazy loading」當成已載入 GIF 的暫停功能，也不以 CSS 隱藏保證停止解碼。一般圖片介面沒有影片式播放控制，需要管理實際動畫來源。
3. 開閱讀器時停止背景圖庫動畫已確認；遮罩覆蓋不一定改變幾何可見範圍，不能只靠可見區判斷。閱讀器只讓目前一頁或兩頁 GIF 播放。
4. 相鄰頁可有限預載，不預先解碼或播放整本漫畫。回到內容頁再依可見範圍恢復播放，是否續播同一幀不作首版承諾。
5. 建議上方資訊封面先用靜態預覽，避免同一張 GIF 在封面及圖庫同時播放；此為建議，不變更使用者要求的下方 GIF 支援。
6. 靜態縮圖放可重建本機快取，控制大小及上限。原始漫畫圖片留在原資料夾，不為這個功能全部再複製進 `.media-viewer/assets/`。

資料依據（2026-10-26 查閱）：

- [MDN Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)：可非同步觀察元素與視窗的交集，作為載入／動畫排程的依據。
- [MDN 圖片載入](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img)：lazy 延後載入，預留尺寸可減少版面跳動；不能推論它會暫停已載入的 GIF。
- [MDN HTMLImageElement](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement)：圖片載入／解碼介面；動畫來源管理仍需另外設計。
- [web.dev：GIF 改影片](https://web.dev/articles/replace-gifs-with-videos)：影片格式可減少動畫資產的檔案量，是後續快取方案候選；本機專案不能直接套用網頁流量數字當成渲染效能結論。轉碼會增加處理流程，首版建議先做可見範圍與播放數管理；若後續採用，只產生快取，不覆寫原圖。

## 6. 已採分工與待細化契約

- CARD 模板決定一筆資料夾卡片；內容資訊模板決定圖 1 上半部。C-76 已確認共用 CELL 編輯能力，但版面分開保存，避免修改其中一處就影響另一處。
- C-85 已採每專案分開保存 CARD 與各內容模板並可攜，每筆閱讀偏好獨立；仍引用穩定欄位身分，不改回舊的全部 project-scoped 值模型。
- 漫畫原圖從已選受管資料夾讀取，renderer 使用受控媒體介面；不把任意絕對路徑當成公開讀檔入口，也不假設目前只讀自訂 assets 的 API 已涵蓋漫畫檔案。
- 作品內容用目前資料夾直接圖片、檔名自然排序（如 1、2、10），封面／閱讀共用清單（C-85）。中央 [檔案檢視](WORKSPACE_REVISION.md#檔案總覽) 與圖片／相簿統一，可彙總子資料夾並保留作品歸屬；不把跨作品彙總清單直接串入同一本閱讀。壓縮檔及 PDF 的既有能力見 [文件檢視器](DOCUMENT_VIEWER_DESIGN.md)。
- 閱讀器保留程式內覆蓋層，另提供系統全螢幕沉浸模式；退出後保留原選取及圖庫捲動位置。
- ESC 建議由最上層先處理：頁碼選單／彈窗 → 沉浸全螢幕 → 閱讀器 → 工作區放大。一次 ESC 不同時退出閱讀與取消 C-74 工作區放大。

## 7. 剩餘規格與驗證

1. 自然排序在同名／特殊字元、缺檔、相同排序值的穩定結果，以及圖片解碼範圍。
2. GIF 返回時的可調排程與資源釋放、省資源模式需先量測；沒有已核定固定 4 張上限。
3. 手動閱讀方向、首張開關與配對還原案例；初始方向可由原型設定可調基線，不再重問已採單頁及現行縮放行為。
4. 閱讀器、選單、輸入與工作區放大的 ESC／焦點驗收，工具列及頁碼選擇的實際互動。
5. 每專案媒體模板與每筆閱讀偏好的版本格式；資訊區／圖庫捲動與 TOP 先回本內容區頂部作可調基線。

需在實作階段驗證空資料夾、損壞圖片、大量高解析圖片／GIF、連續翻頁及切換資料夾時的資源釋放；本輪不安裝套件、不讀取使用者漫畫、不執行原型或測試。
