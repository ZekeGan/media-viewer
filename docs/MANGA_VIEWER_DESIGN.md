# 漫畫資料夾內容與閱讀器

> 此頁持有漫畫內容與閱讀器規則；共用焦點／媒體生命週期見 [UI_RULES](UI_RULES.md)，工作區位置見 [WORKSPACE_REVISION](WORKSPACE_REVISION.md)。相關功能已有首輪實作；契約查 shared/explorer.ts、元件查 FolderContent／Reader。下方「首輪建議／待 schema」屬當時設計細節，不是重做功能的待辦；尚未採用的建議仍未核定。

記錄日期：2026-10-26。來源：使用者漫畫線稿與後續確認。C-76、C-85 已定共用編輯／分版面、可見 GIF、直接圖片自然排序、高度適應／單頁、手動方向、首張獨立預設關閉、程式內覆蓋層、Tooltip／T 顯隱與分層 ESC。視覺風格未定案。

| 資訊配置 | 使用者透過資料夾內容視窗上方工具列，以 CELL 積木方式自訂資訊排列。可配置資訊的範圍與型別後續細化。 |

## 2. 已確認的閱讀視窗（本輪圖 2）

- 視窗採程式內全畫面覆蓋層，退出鍵為 ESC（C-85），不以此承諾獨立原生視窗。
- 點哪張圖，就從該圖開始，而非固定回到第一張。
- 工具列位於上方，從左到右依序為：上一頁、下一頁、寬度自適應、高度自適應、單／雙頁、頁碼 SELECT、隱藏工具列。每項都需要快捷鍵。
- 雙頁時頁碼選項顯示區間，例如 `1–2`、`20–21`；這些是格式例子，不表示已決定封面及奇偶頁配對規則。

## 3. 已核定快捷鍵與工具行為建議

鍵位依 C-76 已核定；C-85 已採高度適應／單頁、手動方向／首張獨立、Tooltip 與 T 手動顯隱。其餘數值及復原時機仍屬可調基線。

| 功能 | 已核定鍵位 | 建議行為 |
| --- | --- | --- |
| 上一頁 | ← | 單頁前一張；雙頁前一組。第一組停用，不循環。 |
| 下一頁 | → | 單頁後一張；雙頁後一組。最後一組停用，不循環。 |
| 寬度自適應 | W | 依閱讀區可用寬度等比縮放，長頁允許垂直捲動，不裁切。雙頁依整組可用寬度計算。 |
| 高度自適應 | H | 優先放進可用高度；若寬度超出，縮到寬度界線內。置中、保留留白、不拉伸。建議作為初始模式。 |
| 單／雙頁 | D | 手動切換，預設單頁；切換時保留目前圖片的定位。雙頁規則見下節。 |
| 頁碼選擇 | G | 聚焦可搜尋的頁碼選擇器，單頁顯示頁碼，雙頁顯示區間，Enter 跳轉。大量選項避免全部同時渲染。 |
| 隱藏／顯示工具列 | T | 手動切換；隱藏後可再按 T，或將滑鼠移到頂緣叫出。先不加入閒置倒數自動隱藏。 |
| 退出閱讀 | ESC | 已確認的退出動作；若頁碼選單等覆蓋層開著，建議先關最上層。 |

適應寬／高都不裁掉漫畫內容；計算可用空間時扣除工具列占用區。圖片比例不同時，不把雙頁各自硬拉成相同寬高。切換圖片建議回到新頁頂端，調整視窗則重算縮放但不更換頁碼。

工具按鍵以 Hover／鍵盤聚焦的 Tooltip 顯示快捷提示（C-76、C-85），例如「寬度適應　W」；按鈕標示目前模式。輸入欄位、頁碼搜尋或選單操作中不攔截打字及游標鍵；尚未實作。

## 4. 已採單／雙頁方向與配對基線（C-85）

- **首版先手動切換、預設單頁**，降低視窗變寬就意外換頁或改配對的情況。
- 建議提供左至右／右至左設定，由使用者依內容選擇；預設方向尚未決定，不因資料夾分類而寫死。
- C-85 採首張獨立的手動開關，不再自動推定首圖是封面；未來其他特殊配對需求另行提出，不由分類猜測。
- 建議將選項改名為「首張獨立顯示」，預設關閉，只在雙頁模式生效。開啟時為 `1`、`2–3`、`4–5`；關閉時為 `1–2`、`3–4`、`5–6`，不自動推定第一張是封面。
- 放在單／雙頁按鈕的閱讀選項 Popup，讓使用者看到配對結果，與 Tooltip 分開；C-85 已採每筆閱讀偏好獨立保存，具體可攜 schema 待設計，不變更分類或原圖。
- 頁碼區間依檔案順序表示；右至左只改左右擺放。建議 ←／→ 仍分別對應上一組／下一組，是否另提供閱讀方向快捷鍵模式待議。
- 尾端剩一張時單獨置中；不把它放大填滿兩頁，不把封面或缺頁誤當成空白圖片。
- 一個圖片檔本身已是跨頁時，可手動回單頁；自動辨識寬圖及自動配對先保留後續，不列首版必做。

## 5. GIF：已確認原則與效能細則

大量動圖會持續涉及圖片解碼與繪製。圖片尺寸、幀數、播放數量及設備都會影響成本，不能只按檔案數承諾順暢；以下是工程判斷，目前未執行本專案 GIF 效能測試。

| 選項 | 體驗與取捨 |
| --- | --- |
| **可見範圍播放，視窗外停止（已選）** | 可見範圍內的 GIF 播放，離開後停止。使用者未採用固定播放數上限；先前的 4 張只是原型建議，不得直接套成產品限制。 |
| 靜態縮圖，Hover／點按才播放（未選） | 保留作省資源模式候選，不替代目前已選的可見範圍播放行為。 |

已確認原則與建議實作細則：

1. 可見區播放、離開停止已確認。技術上建議替換靜態預覽／卸載動畫來源並保留占位；附近可預載縮圖，但不可因此在可見範圍外播放。圖片很多時再配合可視範圍渲染，不限制可瀏覽的總數。
2. 不能把「lazy loading」當成已載入 GIF 的暫停功能，也不以 CSS 隱藏保證停止解碼。一般圖片介面沒有影片式播放控制，需要管理實際動畫來源。
3. 開閱讀器時停止背景圖庫動畫已確認；遮罩覆蓋不一定改變幾何可見範圍，不能只靠可見區判斷。閱讀器只讓目前一頁或兩頁 GIF 播放。
4. 相鄰頁可有限預載，不預先解碼或播放整本漫畫。回到內容頁再依可見範圍恢復播放，是否續播同一幀不作首版承諾。
5. 建議上方資訊封面先用靜態預覽，避免同一張 GIF 在封面及圖庫同時播放；此為建議，不變更使用者要求的下方 GIF 支援。
6. 靜態縮圖放可重建本機快取，控制大小及上限。原始漫畫圖片留在原資料夾，不為這個功能全部再複製進 `.media-viewer/assets/`。

資料依據（2026-10-26 查閱）：

- [MDN Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)：可非同步觀察元素與視窗的交集，作為載入／動畫排程的依據。
- [MDN 圖片載入](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/img)：lazy 延後載入，預留尺寸可減少版面跳動；不能推論它會暫停已載入的 GIF。
- [MDN HTMLImageElement](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement)：圖片載入／解碼介面；動畫來源管理仍需另外設計。
- [web.dev：GIF 改影片](https://web.dev/articles/replace-gifs-with-videos)：影片格式可減少動畫資產的檔案量，是後續快取方案候選；本機專案不能直接套用網頁流量數字當成渲染效能結論。轉碼會增加處理流程，首版建議先做可見範圍與播放數管理；若後續採用，只產生快取，不覆寫原圖。

## 6. 已採分工與待細化契約

- CARD 模板決定一筆資料夾卡片；內容資訊模板決定圖 1 上半部。C-76 已確認共用 CELL 編輯能力，但版面分開保存，避免修改其中一處就影響另一處。
- C-85 已採每專案分開保存 CARD 與各內容模板並可攜，每筆閱讀偏好獨立；仍引用穩定欄位身分，不改回舊的全部 project-scoped 值模型。
- 漫畫原圖從已選受管資料夾讀取，renderer 使用受控媒體介面；不把任意絕對路徑當成公開讀檔入口，也不假設目前只讀自訂 assets 的 API 已涵蓋漫畫檔案。
- 圖片先用目前資料夾直接圖片、檔名自然排序（如 1、2、10），封面／閱讀共用清單（C-85）；遞迴合併、壓縮檔及 PDF 後議。
- 建議閱讀器採應用程式內全畫面覆蓋層，退出後保留原選取及圖庫捲動位置；是否需要作業系統全螢幕另議。
- ESC 建議由最上層先處理：頁碼選單／彈窗 → 閱讀器 → 工作區放大。一次 ESC 不同時退出閱讀與取消 C-74 工作區放大。

## 7. 剩餘規格與驗證

1. 自然排序在同名／特殊字元、缺檔、相同排序值的穩定結果，以及圖片解碼範圍。
2. GIF 返回時的可調排程與資源釋放、省資源模式需先量測；沒有已核定固定 4 張上限。
3. 手動閱讀方向、首張開關與配對還原案例；初始方向可由原型設定可調基線，不再重問已採單頁／高度適應。
4. 閱讀器、選單、輸入與工作區放大的 ESC／焦點驗收，工具列及頁碼選擇的實際互動。
5. 每專案媒體模板與每筆閱讀偏好的版本格式；資訊區／圖庫捲動與 TOP 先回本內容區頂部作可調基線。

需在實作階段驗證空資料夾、損壞圖片、大量高解析圖片／GIF、連續翻頁及切換資料夾時的資源釋放；本輪不安裝套件、不讀取使用者漫畫、不執行原型或測試。
